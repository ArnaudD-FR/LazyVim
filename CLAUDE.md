# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

This is a personal Neovim configuration built on [LazyVim](https://github.com/LazyVim/LazyVim) (a distribution layered on top of the [lazy.nvim](https://github.com/folke/lazy.nvim) plugin manager).

## Layout

- `init.lua` — entry point. Bootstraps via `require("config.lazy")`, then sets global editor options (note: **4-space indent / expandtab** for editing files) and a couple of custom visual-mode keymaps.
- `lua/config/` — loaded automatically by LazyVim at fixed points:
  - `lazy.lua` — bootstraps lazy.nvim, registers the `LazyVim/LazyVim` spec and auto-imports everything under `lua/plugins/`. `defaults.lazy = false` (custom plugins load at startup, not lazily).
  - `options.lua` (before startup), `keymaps.lua` / `autocmds.lua` (on `VeryLazy`). These extend, not replace, the LazyVim defaults.
- `lua/plugins/*.lua` — each file `return`s a lazy.nvim spec (a table or list of tables). Every file in this directory is auto-loaded; filenames are arbitrary.
- `lazyvim.json` — which LazyVim **extras** are enabled (e.g. `ai.claudecode`, `lang.python`, `lang.clangd`). Edit this rather than copying extra specs by hand.
- `lazy-lock.json` — pinned plugin commits. Managed by lazy.nvim; regenerated by `:Lazy sync`/`:Lazy update`, not hand-edited except for surgical removals.

## How plugin specs compose (the key concept)

Multiple spec files can target the **same plugin**; lazy.nvim merges them. This is how this config customizes LazyVim's built-in plugins without forking them:

- `opts` tables are deep-merged (`vim.tbl_deep_extend`), so **list-valued opts get overwritten, not appended**. To add to a list (e.g. `ensure_installed`), use the function form and `vim.list_extend(opts.x, {...})` — see `lua/plugins/jinja.lua` and `lua/plugins/lsp.lua` for the established pattern.
- Disable a default plugin with `{ "owner/plugin", enabled = false }` (see `lua/plugins/flash.lua`).
- Override the colorscheme by passing `opts.colorscheme` to the `LazyVim/LazyVim` spec (see `lua/plugins/colorscheme.lua`; active scheme is `kanagawa`).
- `lua/plugins/example.lua` is the LazyVim sample file — it short-circuits with `if true then return {} end` and loads nothing. It's a reference, not active config.

Adding an LSP server is two steps: register it under `nvim-lspconfig`'s `opts.servers`, and add its Mason package to `mason.nvim`'s `ensure_installed`.

## Commands

There is no build or test suite — this is editor config. Useful operations:

- `stylua .` — format Lua. Config in `stylua.toml`: **2-space indent, column width 120** (distinct from the 4-space setting in `init.lua`, which applies to files you *edit*, not to this repo's own Lua).
- Inside Neovim: `:Lazy` (manage/sync/update/clean plugins), `:Mason` (manage LSP servers/tools/formatters), `:LazyHealth` / `:checkhealth` (diagnose).
- After changing plugin specs, run `:Lazy sync` to install/remove/update accordingly.
